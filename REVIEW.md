# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72-74) | Returns HTTP 200 without checking if MongoDB is reachable. Violates contract requiring HTTP 503 when the database fails. | Stop MongoDB and call `GET /health`; returns 200 `{"status": "ok"}` instead of 503. | Pinned MongoDB readiness with `client.admin.command('ping')` inside a `try/except` block, raising `HTTPException(503, "Database unavailable")` on connection or timeout error. |
| 2 | `compute_late_minutes` (lines 34-36) | Replaces hour and minute directly on naive/UTC `punch_in` datetime without converting to IST, mixing UTC instant with IST shift start. | Punch in at 09:35 IST (04:05 UTC); `(04:05 UTC - 09:30 UTC)` evaluates to negative hours, returning 0 late minutes. | Converted `punch_in` instant to IST (UTC+05:30) timezone before computing elapsed duration against shift start on the attendance date. |
| 3 | `compute_late_minutes` (lines 36-37) | Compares truncated integer minutes `if minutes > 10` after integer floor division, failing grace period at seconds cutoff (R2). | Punch in at 09:40:01 IST for a 09:30 shift: `601 // 60` is 10, `10 > 10` evaluates to False, returning 0 instead of 10. | Computed `elapsed_seconds = (punch_in_ist - shift_start_dt).total_seconds()` and checked `if elapsed_seconds > 600: return int(elapsed_seconds // 60) else: 0`. |
| 4 | `compute_late_minutes` (line 35) | Fails on overnight shifts (R1, R2). Replacing hour on a post-midnight punch-in sets `start` to future evening. | Employee on 22:00-06:00 shift punches in at 01:00 IST on July 7; `punch_in.replace(hour=22)` sets start to July 7 22:00 (21 hours in future), giving 0 late minutes instead of 180. | Defined shift start against the record's true attendance date (July 6), correctly computing elapsed duration across midnight. |
| 5 | `compute_work_hours` (line 41) | Uses Python built-in `round()`, which performs IEEE 754 Banker's Rounding (round half to even) instead of half-up (R4). | Duration of 7650 seconds (2.125 hours): `round(2.125, 2)` gives `2.12` instead of required `2.13`. | Implemented Decimal rounding with `Decimal.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`. |
| 6 | `compute_overtime` (line 47) | Returns all elapsed minutes > 0 (`max(0, ...)`), missing the 30-minute minimum threshold (R3). | Punch out 15 minutes after shift end (18:45 for 18:30 shift); returns 15 overtime minutes instead of 0. | Added threshold check: return `minutes` only if `minutes >= 30`, otherwise return `0`. |
| 7 | `compute_overtime` (lines 45-47) | Computes shift end on the record calendar date, failing on overnight shifts where shift ends on the next calendar day (R1, R3). | Shift 22:00-06:00 on 2026-07-06, punch out at 06:40 on July 7; compared against July 6 06:00, yielding 1480 overtime minutes instead of 40. | When `shift_end <= shift_start`, set shift end date to `attendance_date + timedelta(days=1)`. |
| 8 | `compute_overtime` (lines 46-47) | Replaces timezone with `tzinfo=IST` on `end`, but `punch_out` from MongoDB may be naive UTC, raising `TypeError`. | Subtraction `punch_out - end` crashes with `TypeError: can't compare offset-naive and offset-aware datetimes`. | Normalized `punch_out` to IST timezone before calculating difference against `shift_end_dt`. |
| 9 | `create_employee` (lines 78-85) | Relies on check-then-insert (`find_one` then `insert_one`), susceptible to race conditions and duplicate creation under concurrency. | Send two concurrent `POST /employees` requests with identical `emp_code`; both pass check and insert duplicates, or return 500 without unique index handling. | Created a unique index on `emp_code` at startup, and caught `DuplicateKeyError` to return HTTP 409 Conflict. |
| 10 | `create_employee` (lines 53-61, 82) | Missing schema validation for shift equality and regex patterns; returns datetime object instead of epoch milliseconds. | Submit `shift_start="09:00"` and `shift_end="09:00"` (accepted with 201 instead of 422); response `created_at` serializes as ISO string rather than epoch milliseconds integer. | Added Pydantic field patterns, custom validator ensuring `shift_start != shift_end`, and serialized `created_at` as epoch milliseconds integer. |
| 11 | `list_employees` (line 93) | Off-by-one pagination bug: calculates `skip = page * page_size` for 1-indexed pagination (R10), skipping page 1 entirely. | Request `GET /employees?page=1&page_size=20`; skips first 20 employees, returning records 21-40. | Changed skip calculation to `skip = (page - 1) * page_size`. |
| 12 | `list_employees` (lines 94-95) | `total` counts full collection ignoring filters (R10); missing sorting by `emp_code` ascending. | Query `GET /employees?department=Engineering`; `total` returns total headcount across all departments instead of Engineering count, and results lack deterministic order. | Used `db.employees.count_documents(q)` to respect filter, added `.sort("emp_code", 1)`, and formatted epoch milliseconds. |
| 13 | `punch_in` (lines 101, 113) | Missing check for non-existent employee; accessing `emp["shift_start"]` on `None` throws unhandled 500 error. | Punch in with non-existent `emp_code="EMP9999"`; crashes with `TypeError: 'NoneType' object is not subscriptable` (HTTP 500) instead of 404. | Added verification `if not emp: raise HTTPException(404, "Employee not found")`. |
| 14 | `punch_in` (lines 104-118) | Check-then-insert race condition on `(emp_code, date)` allows duplicate punch-ins for the same day. | Fire simultaneous punch-in requests for same employee; both insert duplicate records or raise 500. | Enforced compound unique index `[("emp_code", 1), ("date", 1)]` on `attendance_logs` and caught `DuplicateKeyError` to return 409 Conflict. |
| 15 | `punch_in` (lines 102-103) | Attendance date calculation ignores overnight shifts (R1); timestamps parsed using local machine timezone. | Employee on 22:00-06:00 shift punches in at 01:00 IST on July 7; record assigned date `2026-07-07` instead of `2026-07-06`. | Applied R1 overnight shift rule: if `shift_end <= shift_start` and IST time < `shift_end`, date is set to previous calendar day. |
| 16 | `punch_in` (line 119) | Injects `"id": str(res.inserted_id)` into response document, violating OpenAPI schema contract where attendance records have no id field. | Schema validation fails on client/grader because `id` is an unexpected property. | Omitted MongoDB `_id` and removed generated `"id"` key from the returned document. |
| 17 | `list_attendance` (lines 144-147) | Scale collapse: loads entire collection into memory with `list(db.attendance_logs.find(q))`, sorting and slicing in Python. | High memory footprint and severe latency on 100,000 documents; causes query timeouts under load. | Executed filtering, sorting, and pagination directly in MongoDB using `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)` backed by indexes. |
| 18 | `list_attendance` (lines 125-150) | Missing date range validation (`date_from > date_to`), missing secondary sort by `emp_code`, and unauthorized `"id"` field returned. | Query `GET /attendance?date_from=2026-07-10&date_to=2026-07-01` returns 200 with empty list instead of HTTP 422; records contain internal `id`. | Added validation `if date_from > date_to: raise HTTPException(422)`, added secondary sort `emp_code: 1`, formatted dates to epoch milliseconds, and removed `id`. |

### Items examined and verified as NOT defective

   - Lines 18-23: Reads from `os.getenv(...)` with local `.env` fallback. Python's `os.getenv` prioritizes actual environment variables already injected into the process over `.env` defaults, meeting the requirement in Section 4.
2. **Collection names (`employees`, `attendance_logs`)**:
   - Matches the data model specification and sample dataset exactly.
3. **Pydantic / FastAPI application architecture in a single file**:
   - `app/main.py` is structured as a self-contained module executable via `uvicorn app.main:app --port 8000`, matching submission requirements.
